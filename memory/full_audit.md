## ЧАСТЬ 1: БАГИ, ОБНАРУЖЕННЫЕ В РЕЗУЛЬТАТАХ (скриншоты)

Это **реальные проблемы**, видимые получателям в письмах.

---

### 🔴 БАГ #1: Нераскрытый спинтакс `{` виден в письме (КРИТИЧЕСКИЙ)

**Скриншоты:** photo_2 (от Emma), photo_6 (от Olivia)

Текст письма начинается с видимой фигурной скобки:
```
{so I was scrolling earlier and this thing caught my eye...
```

> [!CAUTION]
> Получатель видит символ `{` в начале письма! Это значит спинтакс **не раскрылся** — вероятнее всего сработала ловушка `{{` (двойная скобка). Парсер вырезал часть текста как «переменную», а остаток отдал как есть. Это **мгновенный маркер спама** для получателя.

**Причина:** В шаблоне тела (ультра-минималистичный стиль, шаблон #4) вероятно есть конструкция где `{` стоит в начале, а перед ней — другая `{` из внешнего контекста, или парсер не обработал один из уровней вложенности.

**Исправление:** Проверить шаблон #4 (ультра-минимализм, тёмный фон) на наличие `{{` ловушки.

---

### 🔴 БАГ #2: HTML-сущность `&mdash;` не рендерится (КРИТИЧЕСКИЙ)

**Скриншот:** photo_7 (от me, тема "TSB1250 did you catch this")

Текст в письме:
```
fyi, TSB1250 &mdash; there are some members from near you...
```

> [!CAUTION]
> Вместо тире «—» получатель видит сырой текст `&mdash;`. Это происходит потому, что шаблон использует HTML-сущность `&mdash;` **внутри колоночного layout**, но из-за автоматической HTML entity randomization софта (который заменяет случайные буквы на entities) — оригинальная `&mdash;` может быть повреждена, либо почтовик не рендерит её в данном контексте.

**Причина:** Использование `&mdash;` в шаблоне. Софт применяет HTML Entity Randomization поверх, что может конфликтовать.

**Исправление:** Заменить `&mdash;` на обычное UTF-8 тире `—` (символ, а не HTML entity) во всех шаблонах. Или использовать спинтакс `{ —|,| -}` для вариативности.

---

### 🟡 БАГ #3: Имена из базы выглядят как технические ID (ВИЗУАЛЬНЫЙ)

**Скриншоты:** photo_3 (от Rachel — "hey TSB,"), photo_7 (от me — "TSB1250"), photo_11 (от me — "TSB1250"), photo_13 (от me — "TSB"), photo_14 (от Amanda — "TSB1250")

> [!WARNING]
> Имена `TSB`, `TSB1250`, `Bog264`, `Gaz`, `GazTormoz` — это технические/тестовые записи из CSV-базы, а не реальные имена. Когда такое имя попадает в письмо ("hey TSB,", "fyi, TSB1250"), оно выглядит максимально роботизированно и неестественно.

**Это НЕ баг промпта/шаблона** — это проблема тестовых данных в базе. Но промпт мог бы содержать рекомендацию: «Убедись, что в CSV-базе поле name содержит реальные человеческие имена, а не логины/ID».

### 🟡 БАГ #4: Голая ссылка (URL) выглядит как спам в Plain Text письмах

**Скриншоты:** photo_8, photo_9, photo_10, photo_11, photo_12, photo_13, photo_14, photo_15

Во всех Plain Text письмах ссылка отображается как огромный URL:
```
https://www.google.com/url?q=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3DNwAt56d1tac%26pp%3DygURY2xhdWRIIGZhYmxlIHZpZXc%253D%26cb%3Dh6c57vu%26ref%3Dmuqrmt%26extra%3Dkpb1oed%26rand%3Dbhp7%26sessionID%3Dnp3a%26ver%3D30e8vd%26ts%3D1717483832%26token%3D3g8r344%23x2245&e=le0jzdl3
```

> [!WARNING]
> Это **не баг шаблона** — это следствие работы софта (GET-параметры + редирект-домены). Но длина ссылки (200+ символов) в plain text выглядит **крайне подозрительно**. Живой человек никогда не пришлёт такой URL. Также видно, что используется `google.com/url?q=...` как редиректор — Google Translate и VK-away редиректы — это известные «серые» приёмы, которые Gmail может отслеживать.

**Рекомендация для софта:** Использовать короткие чистые домены для ссылок (например, `https://example.com/abc123` вместо стекинга Google/VK редиректов с десятком GET-параметров).

## ЧАСТЬ 3: СВОДКА И ПРИОРИТЕТЫ

### 🔴 Критические (нужно исправить СЕЙЧАС):

1. **Баг `{` в письмах** — нераскрытый спинтакс виден получателю (photo_2, photo_6). Нужно найти и исправить шаблон с `{{` ловушкой.
2. **Баг `&mdash;`** — HTML-сущность рендерится как сырой текст (photo_7). Заменить на UTF-8 символ `—`.
3. **Ложный пример ошибки** `{option A|{option B|option C}}` во всех промптах — он вводит ИИ в заблуждение, заставляя избегать конструкций, которые на самом деле безопасны. Нужно заменить на реальный пример ошибки: `{{option B|option C}|option A}`.
4. **Сбитая нумерация 4.1/4.2/3.3/3.4/4.5** в промпте 3 — путает нейросеть при генерации.

### 🟡 Средние (стоит исправить):

5. **Счётчики проверок** во всех 3 промптах не совпадают с реальным количеством чекбоксов (5→8, 6→11, 6→11).
6. **Противоречие «≤100 символов сырого текста»** в промпте 1 — невозможно при 3-4 уровнях вложенности. Убрать это ограничение или увеличить до 300+.
7. **Таблица распределения** в промпте 3 написана для Plain Text, а файл предназначен для HTML.

### 🟢 Косметические:

8. **`&#x20;` и Markdown-артефакты** по всем файлам — не влияют на ИИ критически, но загрязняют промпт.
